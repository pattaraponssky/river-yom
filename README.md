# River Yom (ระบบติดตามสถานการณ์น้ำระยะไกลอัตโนมัติ ฝั่งขวาแม่น้ำยม)

ระบบช่วยตัดสินใจในการบริหารจัดการน้ำ พื้นที่ฝั่งขวาแม่น้ำยม อำเภอบางระกำ จังหวัดพิษณุโลก
พัฒนาขึ้นภายใต้แนวคิด **Intelligent Water Management** โดยผสานแบบจำลองอุทกวิทยาและชลศาสตร์
มาตรฐานสากล (HEC-HMS, HEC-RAS, HEC-DSSVue) เข้ากับการทำงานอัตโนมัติเต็มรูปแบบ เพื่อพยากรณ์และ
วิเคราะห์สถานการณ์น้ำ สนับสนุนการตัดสินใจควบคุมโครงสร้างระบายน้ำ (เปิด-ปิดประตูระบายน้ำ) และลด
ความเสี่ยงจากข้อผิดพลาดของมนุษย์

ระบบจะรันอัตโนมัติทุกวันในช่วงเวลา **08:00 น.** (และรันซ้ำอีกรอบเวลา 09:00 น.) โดยดึงข้อมูลจาก
แหล่งข้อมูลต่าง ๆ มาประมวลผล แล้วนำผลลัพธ์ไปแสดงบนเว็บแอปพลิเคชัน

## ภาพรวมระบบ

ระบบประกอบด้วยส่วนหลัก 3 ส่วน:

1. **ระบบประมวลผลแบบจำลอง (Modeling Engine)** — ใช้ HEC-HMS จำลองปริมาณน้ำท่า, HEC-RAS
   จำลองการไหลของน้ำในแม่น้ำ/โครงสร้างควบคุมน้ำ และ HEC-DSSVue จัดการ/แปลงข้อมูลอนุกรมเวลา
   (Time-Series) ผ่านไฟล์ `.dss` เป็นตัวกลางเชื่อมโยงระหว่างแบบจำลอง
2. **ระบบนำเข้าข้อมูล (Data Ingestion)** — ดึงข้อมูลน้ำฝน–น้ำท่าย้อนหลังและพยากรณ์ผ่าน API ของ
   หน่วยงานที่เกี่ยวข้อง เช่น กรมชลประทาน, กรมอุตุนิยมวิทยา, สถาบันสารสนเทศทรัพยากรน้ำ (สสน.)
3. **เว็บแอปพลิเคชัน (Web Application)** — แสดงผลข้อมูลในรูปแบบที่เข้าใจง่าย เช่น แผนที่สถานี,
   กราฟระดับน้ำ/อัตราการไหล, เกณฑ์เฝ้าระวังเตือนภัย, ผลพยากรณ์ล่วงหน้า 7 วัน, รูปตัดตามยาวแม่น้ำ
   และแผนผังลุ่มน้ำ

│  │  ├─ components/     # เมนูของคอมโพเนนต์

## สิทธิ์การใช้งานระบบ

ระบบรองรับผู้ใช้งาน 3 ระดับ ผ่านหน้าเว็บที่มีทั้งแบบลงชื่อเข้าใช้ (Sign In) และแบบสาธารณะ (Public):

1. **ผู้ดูแลระบบ (Admin)** — ต้องลงชื่อเข้าใช้งานทุกครั้ง จัดการบัญชีผู้ใช้งานทั้งหมด, นำเข้าข้อมูล
   ตรวจวัดจากแหล่งข้อมูลต่าง ๆ (กรมอุตุนิยมวิทยา, สสน.), เรียกดูและส่งออกข้อมูลเพื่อวิเคราะห์ต่อ
2. **ผู้ปฏิบัติงาน (User)** — ต้องลงชื่อเข้าใช้งานทุกครั้ง เรียกดูข้อมูลตรวจวัดย้อนหลังและผลจากแบบจำลอง
   ส่งออกข้อมูลเพื่อวิเคราะห์เพิ่มเติมได้ แต่ตั้งค่าบัญชี/ระบบไม่ได้
3. **ผู้ใช้งานทั่วไป (Public)** — ไม่ต้องลงชื่อเข้าใช้ ดูข้อมูลย้อนหลัง ผลพยากรณ์ และส่งออกข้อมูลได้
   (มีการจำกัดจำนวนการสืบค้น/ส่งออก)

## ขั้นตอนการทำงานของระบบ (Pipeline)

ระบบทำงานอัตโนมัติทุกวันตามลำดับ 6 ขั้นตอนหลัก รวมไว้ในไฟล์ `run-all.bat` ไฟล์เดียว เพื่อให้ควบคุม
ง่าย ลดความซับซ้อน และสะดวกต่อการบำรุงรักษา:

1. **การเตรียมข้อมูล** — รวบรวมน้ำฝน–น้ำท่าย้อนหลัง 7 วัน + ฝนพยากรณ์ล่วงหน้า 7 วัน (รวม 14 วัน)
   จาก API ของกรมชลประทาน, กรมอุตุนิยมวิทยา, สสน. แล้วสร้างไฟล์ `input-hms.txt`
2. **แปลงข้อมูลเป็นไฟล์ DSS ด้วย HEC-DSSVue** — แปลง `input-hms.txt` เป็น `input-hms.dss`
   ผ่านสคริปต์ Python/Batch File
3. **จำลองน้ำท่าด้วย HEC-HMS** — ปรับช่วงเวลาการจำลองอัตโนมัติผ่านไฟล์ `.forecast`
   (Start = วันนี้ −7 วัน 07:00 น., Forecast = วันนี้ 07:00 น., End = วันนี้ +6 วัน 06:00 น.)
   ได้ผลลัพธ์เป็นไฟล์ `output-hms.dss`
4. **นำข้อมูลน้ำท่าเข้าสู่ HEC-RAS** — จำลองการไหลแบบ Unsteady Flow ควบคุมด้วย Python script
   ผ่าน `win32com.client` ตั้งค่าช่วงเวลาในไฟล์ `.p01` (หรือ `.p03` ตามเวอร์ชันแผน)
5. **แปลงผลลัพธ์เป็น CSV ด้วย HEC-DSSVue** — แปลงไฟล์ `.dss` เป็น CSV (ระดับน้ำ, อัตราการไหล,
   สถานะประตูระบายน้ำ) โดยระบุ Pathname (ชื่อแม่น้ำ, สถานี, ประเภทข้อมูล FLOW/FLOW-GATE,
   หน่วยเวลา, ชื่อแผน)
6. **แสดงผลผ่านเว็บไซต์** — เว็บไซต์ดึงข้อมูลจากไฟล์ CSV มาแสดงผล เช่น กราฟระดับน้ำและอัตราการไหล

### รูปแบบข้อมูล API

ข้อมูลนำเข้าอยู่ในรูปแบบ JSON แบ่งเป็น 3 กลุ่มหลัก:

- **สถานีเขื่อน/ประตูระบายน้ำ**: `station_name`, `station_code`, `datetime`, `upper_water`,
  `lower_water`, `flow`, `rainfall`, `gate1–gate5`
- **สถานีน้ำท่า**: `stationcode`, `stationname`, `date_time`, `basin`, `district`, `province`,
  `waterlv`, `qwater`
- **สถานีฝน**: `stationcode`, `stationname`, `date_time`, `basin`, `district`, `province`,
  `rainfall`

แหล่งข้อมูลตัวอย่าง: ศูนย์อุทกวิทยาชลประทานภาคกลาง (`http://hydro-2.rid.go.th/`) — น้ำฝนรายวัน
เวลา 07:00 น. และน้ำท่ารายวันเวลา 06:00 น.

## การติดตั้ง

### 1. ติดตั้งโปรแกรม HEC ในตำแหน่งเริ่มต้น (default)

ดาวน์โหลดและติดตั้งตามลำดับ โดยใช้ตำแหน่งติดตั้งเริ่มต้นของแต่ละโปรแกรม:

- [HEC-HMS 4.2.1](https://www.hec.usace.army.mil/software/hec-hms/)
- [HEC-DSSVue](https://www.hec.usace.army.mil/software/dssvue/)
- [HEC-RAS 6.3](https://www.hec.usace.army.mil/software/hec-ras/)

### 2. ติดตั้ง Java JDK เวอร์ชัน 17

1. ดาวน์โหลดจาก [Oracle JDK Downloads](https://www.oracle.com/java/technologies/javase-jdk17-downloads.html)
2. ติดตั้งตามขั้นตอนของ Oracle
3. ตั้งค่าตัวแปรระบบ **JAVA_HOME**
   - **Windows**: System Properties → Advanced → Environment Variables → เพิ่ม `JAVA_HOME`
     ชี้ไปยังตำแหน่งที่ติดตั้ง JDK (เช่น `C:\Program Files\Java\jdk-17`)
   - **Linux/Mac**: เพิ่มในไฟล์ `.bashrc` หรือ `.zshrc`:

     ```bash
     export JAVA_HOME=/path/to/jdk-17
     export PATH=$JAVA_HOME/bin:$PATH
     ```

     แล้วรัน `source ~/.bashrc` หรือ `source ~/.zshrc`

### 3. ติดตั้ง Python

1. ติดตั้ง Python และ**เลือก path เป็น `C:\jython2.7.4`**
2. ตรวจสอบการติดตั้ง:

   ```bash
   python --version
   ```

3. ติดตั้งไลบรารีที่จำเป็น:

   ```bash
   pip install pywin32
   pip install requests
   pip install pandas
   ```

### 4. ติดตั้ง XAMPP

- เลือกตำแหน่งติดตั้งพื้นฐาน (`C:\`)
- ตั้งค่าพอร์ตให้กับ Apache Service — หากทีมติดตั้งใช้ port 80 อยู่แล้ว ให้เปลี่ยนไปใช้ port อื่นแทน
  เพื่อไม่ให้ชนกัน
- ตั้งค่าไฟล์ `php.ini` ให้เปิดใช้งาน extension `intl` โดยลบเครื่องหมาย `;` ด้านหน้าออก:

  ```ini
  extension=intl
  ```

- ตั้งค่า user ของ MySQL พร้อมรหัสผ่าน แล้วนำเข้าฐานข้อมูลของโครงการ (import .sql)

### 5. วางไฟล์โปรเจกต์

1. นำไฟล์โค้ด **Frontend**, **CodeIgniter 4**, และ **Model** ไปไว้ใน Apache server โดยวางไว้ใน
   โฟลเดอร์ `htdocs` (เช่น `C:/xampp/htdocs/river-yom`)

   Build frontend ก่อนนำไปวาง:

   ```sh
   git clone <river-yom-repo-url>
   cd river-yom/frontend
   npm install
   npm run build
   ```

   จากนั้นนำไฟล์ในโฟลเดอร์ `dist` ไปวางในโฟลเดอร์ `htdocs`

### 6. ตั้งค่าไฟล์ Backend

1. กำหนดไฟล์ `.env` ให้ถูกต้อง (ชื่อฐานข้อมูล, user, password ของ MySQL)
2. สร้างไฟล์ `.htaccess` เพื่อปิดการเข้าถึงไฟล์สำคัญของโปรแกรมจากภายนอก

### 7. ให้สิทธิ์การเขียนไฟล์ (สำหรับกรณีสร้างไฟล์ CSV ไม่ได้)

**Linux/Mac:**

```bash
chmod -R 777 /path/to/your/folder
```

หากต้องใช้สิทธิ์ผู้ดูแลระบบ:

```bash
sudo chmod -R 777 /var/www/html/river-yom
```

### 8. ทดสอบระบบ

ทดสอบให้ครบทั้งการเปิดเว็บแสดงผล, การเรียกใช้ API, การรันโมเดลรายวัน และการดึงข้อมูลเข้าสู่ระบบ
ก่อนเปิดใช้งานจริง

## การตั้งค่า Task Scheduler

ตั้งเวลาให้สคริปต์ `run-all.bat` ทำงานอัตโนมัติทุกวัน (ปกติเวลา **08:00 น.** และรันซ้ำอีกรอบเวลา
**09:00 น.**) ด้วย Task Scheduler ของ Windows:

1. เปิดโปรแกรม **Task Scheduler**
2. คลิก **Create Basic Task**
3. กำหนดชื่อและคำอธิบาย เช่น `Run Water Simulation Auto`
4. เลือก Trigger เป็น **Daily** และกำหนดเวลาเป็น `08:00:00` และ `09:00:00`
5. เลือก Action เป็น **Start a program**
6. Browse ไปยังไฟล์ `run-all.bat` ที่จัดเตรียมไว้
7. กด **Finish** เพื่อสร้าง Task
8. ตั้งค่าให้ Task รันได้แม้ผู้ใช้งานไม่ได้ล็อกอินอยู่ (Run whether user is logged on or not)

> `run-all.bat` รวมคำสั่งของขั้นตอนที่ 1–5 ของ pipeline ไว้ในไฟล์เดียว เพื่อความสะดวกในการควบคุมและ
> บำรุงรักษา หากมีการเปลี่ยนแปลงสามารถแก้ไขได้จากไฟล์เดียวโดยไม่ต้องกระจายโค้ดหลายที่

## การตั้งค่า SSL / โดเมน (ถ้ามี)

หากมีโดเมนสำหรับระบบ ให้เตรียมไฟล์ certificate (`.crt`, `.key`, `server-ca.crt`) ไว้ล่วงหน้า แล้ว
ตั้งค่าใน `httpd-vhosts.conf`:

```apache
<VirtualHost *:443>
    ServerName yourdomain.com
    DocumentRoot "C:/xampp/htdocs"
    SSLEngine on
    SSLCertificateFile "C:/xampp/apache/conf/ssl/server.crt"
    SSLCertificateKeyFile "C:/xampp/apache/conf/ssl/server.key"
    SSLCertificateChainFile "C:/xampp/apache/conf/ssl/server-ca.crt"
</VirtualHost>
```

ตรวจสอบให้แน่ใจว่าไฟล์ `httpd.conf` เปิดใช้งานบรรทัดต่อไปนี้:

```apache
LoadModule ssl_module modules/mod_ssl.so
Include conf/extra/httpd-vhosts.conf
Include conf/extra/httpd-ssl.conf
```

## การเปิด Firewall

เปิดพอร์ตที่จำเป็นสำหรับการเข้าถึงเว็บไซต์:

1. เปิด **Windows Firewall** → **Inbound Rules** → **New Rule**
2. เลือกประเภท **Port** → **TCP**
3. ระบุพอร์ต `80` และ `443`
4. อนุญาตการเชื่อมต่อ (Allow the connection)

## การดูแลและบำรุงรักษาระบบ

ระบบมีหน้าเว็บสำหรับผู้ดูแลระบบใช้ทดสอบและบำรุงรักษา ได้แก่:

- **หน้าเตรียมข้อมูลจำลองปริมาณน้ำฝน (HEC-DSS)** — ทดสอบดาวน์โหลดผลพยากรณ์ปริมาณฝนจาก
  กรมอุตุนิยมวิทยา, สร้างไฟล์ TXT และแปลงเป็น DSS
- **หน้าจำลองน้ำท่าจากข้อมูลน้ำฝน (HEC-HMS)** — ทดสอบการแก้ไขวันพยากรณ์และรันโมเดล
  (HEC-HMS Compute)
- **หน้าจำลองสถานการณ์น้ำ (HEC-RAS)** — ทดสอบการแก้ไขวันพยากรณ์ จำลองสถานการณ์น้ำ และดึง
  ข้อมูลออกมาเป็นไฟล์ CSV
- **หน้าทดสอบระบบทั้งหมด** — ทดสอบ pipeline ทั้งหมดตั้งแต่การเตรียมข้อมูลจนถึงรันแบบจำลอง
  ในครั้งเดียว
- **หน้าตั้งค่าสถานี** — ใช้เมื่อมีการเปลี่ยนแปลงสถานีตรวจวัด
- **หน้าอัปเดตข้อมูลด้วยตนเอง** — ใช้เมื่อระบบอัปเดตข้อมูลอัตโนมัติมีปัญหา สามารถอัปโหลดไฟล์
  CSV หรือกำหนดวันที่อัปเดตเองผ่านหน้าเว็บ
- **หน้าจัดการอุปกรณ์ (Equipment Management)** — เพิ่ม/ลบ/แก้ไขข้อมูลอุปกรณ์ที่ใช้ในระบบ
  ติดตามสถานการณ์น้ำ พร้อมดูประวัติการบำรุงรักษาอุปกรณ์

## หมายเหตุเพิ่มเติม

- ควรตรวจสอบว่าพอร์ตที่เลือกให้ Apache Service ใช้งาน ไม่ชนกับโปรแกรมอื่นที่ติดตั้งไว้ในเครื่อง
  เดียวกัน (เช่น IIS หรือระบบอื่นที่ใช้ port 80/443 อยู่ก่อนแล้ว)
- ควรสำรอง (backup) ฐานข้อมูลและไฟล์ `.env` ก่อนอัปเดตระบบทุกครั้ง
- ตรวจสอบไฟล์ `.forecast` และไฟล์ `.p01`/`.p03` ให้ตรงกับรอบการจำลองก่อนรัน pipeline
  แบบ manual
- หากอัปเดตข้อมูลอัตโนมัติล้มเหลว ให้ตรวจสอบ log ของ Task Scheduler และ log ของสคริปต์
  `run-all.bat` เป็นลำดับแรก
